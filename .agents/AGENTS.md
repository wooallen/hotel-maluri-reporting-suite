# Project Rules & Guidelines — Hotel Maluri Reporting Suite

## GitHub Deployment & Actions Troubleshooting Rule
- **Mandatory First Step on Deployment Issues**: Whenever a GitHub Pages build, deployment, or GitHub Actions workflow run is stuck, queued, failing, or delayed, you MUST check `https://www.githubstatus.com/` (or query `https://www.githubstatus.com/api/v2/summary.json`) FIRST before making any code modifications, editing workflow YAML files, or force-pushing branches.
- **Incident Protocol**: If `githubstatus.com` reports an active incident affecting GitHub Actions or Pages, immediately notify the user of the GitHub platform outage rather than attempting to debug local code or workflow configurations.

## Financial Statement Benchmarking & KL 4-Star Hotel Rule
- **Mandatory Kuala Lumpur 4-Star Hotel Benchmarking**: Whenever analyzing financial statements, auditing P&L line items, modeling staff cost intensity, setting P&L targets, or whenever a new financial/management report file is uploaded or introduced, the Agent MUST ALWAYS compare the financial and operational performance of Hotel Maluri against similar 4-Star Hotels in Kuala Lumpur as a benchmark.
- **Mandatory NotebookLM Integration**: You MUST leverage Google NotebookLM (via MCP tools or `nlm` CLI) to research, ingest newly uploaded files/data into NotebookLM notebooks (e.g. `Hotel Maluri & KL 4-Star Hospitality Benchmarks`), query KL 4-star hospitality benchmarks, labor market ratios (e.g. 0.45 staff/room, 35.0% payroll-to-revenue target, RM 240–310 ADR target, 65–72% occupancy target, 30–36% GOP margin target), and generate comparative analysis reports.
